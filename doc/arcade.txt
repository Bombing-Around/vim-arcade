1. INTRO                                                        *arcade-intro*

vim-arcade renders games into an unmodifiable scratch buffer and drives them
from buffer-local normal-mode mappings. Requires Vim 8.0+ or any Neovim.
Written in legacy VimScript so one implementation serves both.

Colour comes from |textprop| (Vim) or extmarks (Neovim); on a build with
neither, the games still play, just monochrome.

==============================================================================
2. COMMANDS                                                  *arcade-commands*

                                                                    *:Arcade*
:Arcade {game}      Start {game}. Completes on "2048", "crawl" and "sort".

                                                                *:Arcade2048*
:Arcade2048         Start 2048.

                                                               *:ArcadeCrawl*
:ArcadeCrawl        Start the dungeon crawler.

                                                                *:ArcadeSort*
:ArcadeSort         Start the ball sort puzzle.

                                                              *:ArcadeScores*
:ArcadeScores       Print the best score and the last runs of each game.

3. 2048                                                          *arcade-2048*

Slide tiles until two equal tiles touch; they merge and score their sum.

    h j k l  <Left> <Down> <Up> <Right>   slide
    u                                     undo (8 levels)
    r                                     restart
    q  <Esc>                              quit

The run is recorded when the board locks up or you quit.

==============================================================================
4. CRAWL                                                        *arcade-crawl*

A turn-based dungeon. Levels are generated per descent; monsters act only
when they can see you; field of view is recursive shadowcasting.

    h j k l                               move west/south/north/east
    y u b n                               move diagonally
    <Left> <Down> <Up> <Right>            move
    .                                     wait a turn
    p                                     drink a potion
    >                                     descend the stairs you stand on
    ?                                     toggle help
    r                                     restart at depth 1
    q                                     quit

<Esc> is disabled while a run is in progress -- it only echoes a reminder
to press q, rather than discarding a dungeon you may be several depths
into. It closes the game normally once a run has ended.

Glyphs: >
    @  you                 >  stairs down       $  gold
    !  potion              /  weapon (+1 atk)   [  armor (+1 def)
    "  Amulet of Yendor    r k g o W T D  monsters, ascending nastiness
<
Walking into a monster attacks it. Damage is |atk| + 0..2 - target |def|,
minimum 1. Killing grants xp; levelling raises max hp, heals you somewhat and
raises attack (and defence every third level). You regain 1 hp every 20
turns.

Score is gold + 25 per character level + 50 per depth reached, plus 500 for
carrying out the Amulet of Yendor, which lies on the deepest level
(|g:arcade_crawl_depth|).

5. SORT                                                          *arcade-sort*

Tubes of coloured balls, one hand. Stack every colour into a tube of its own.

    h l  <Left> <Right>                   move the hand between tubes
    <Space>  <CR>                         lift the top run, or drop it
    u                                     undo (32 steps; returns a handful)
    ?                                     hint: point at a move (costs one)
    t                                     take a spare tube (costs one)
    z                                     toggle zen
    r                                     reshuffle this level
    R                                     abandon the run, deal a new one
    q                                     save and quit

Balls drop onto an empty tube, or onto a tube whose top ball is the same
colour and which still has room; dropping them back where they came from is
always allowed and costs no move. Each colour is also a distinct shape, so
the board reads on a monochrome build.

A |count| applies as it does anywhere else: >
    2<Space>    lift two balls of a run of three
    1<Space>    drop one of the handful you are carrying
    3l          walk three tubes to the right
<
Dropping into a tube with less room than you are carrying puts in what fits
and leaves the rest in hand, which is the same manoeuvre without counting.
A handful is always one colour, one undo step covers a whole drop, and the
move counter counts balls, so par and score mean the same thing whether a
run moves in one keystroke or three.

Levels run from four colours up to nine, always with two spare tubes. A
level is dealt by walking backwards from a solved board along inverted
moves, so every level is winnable -- but a careless line of play can still
strand the board with no legal move.

There are no points. A cleared level is worth the number of moves it took,
each level keeps its own record, and beating it is what the banner says.
A run's tally is simply how many levels it cleared.

? and t are help, and help is not free: a hint costs a move and so does a
spare tube, of which there are two a level. A hint ranks the legal moves --
finish a tube, empty a tube, add to a colour, anything -- rather than
consulting the solution the level was dealt from, which goes stale as soon
as the board leaves the dealt position. An unlimited supply of spare tubes
would solve every board, hence the two.

                                                          *g:arcade_sort_zen*
z toggles zen: no records, no tally, just the board and the move count. A
zen run is never written to the scoreboard and never touches a level
record. Set g:arcade_sort_zen to start every run that way.

<Esc> is disabled, as in |arcade-crawl|: it is muscle memory in normal mode
and a run here can be many levels deep, so it stays put and points at q.

A run has no end -- the levels keep coming -- so the game is written down
whenever it closes, by q or by the buffer going away (|:bwipeout|, a closed
tab, or Vim quitting). The next :ArcadeSort picks the run up where it was
left, and R abandons it for a fresh one. Saved games live beside the scores
in |g:arcade_data_dir| and are best effort: a missing, unreadable or
inconsistent one just deals a new board.

A run that spans several sittings is one row in |:ArcadeScores|, updated
each time it is put down, rather than a row per quit.

6. OPTIONS                                                    *arcade-options*

                                                             *g:arcade_window*
g:arcade_window        string (default "tab")
        Where the game surface opens: "tab", "split", "vsplit" or "current".

                                                              *g:arcade_ascii*
g:arcade_ascii         boolean (default: on unless 'encoding' is utf-8)
        Draw with ASCII instead of box-drawing characters.

                                                          *g:arcade_sort_zen*
g:arcade_sort_zen      boolean (default 0)
        Start ball sort runs in zen: no scoring, no records.

                                                        *g:arcade_crawl_depth*
g:arcade_crawl_depth   number (default 8)
        Depth at which the Amulet of Yendor appears.

                                                          *g:arcade_data_dir*
g:arcade_data_dir      string
        Where scores.json lives. Defaults to stdpath("data")/vim-arcade on
        Neovim and $XDG_DATA_HOME/vim-arcade (else ~/.local/share/vim-arcade)
        on Vim. Score writing is best effort; a read-only path never breaks
        a game.

7. HIGHLIGHTS                                              *arcade-highlights*

All groups are defined with |:highlight-default|, so a colorscheme or your
vimrc wins. 2048 uses Arcade2048Title, Arcade2048Score, Arcade2048Hint,
Arcade2048Win, Arcade2048Over, Arcade2048Empty and Arcade2048T{2..4096}.
Crawl uses ArcadeCrawlStatus, ArcadeCrawlWall, ArcadeCrawlFloor,
ArcadeCrawlDim, ArcadeCrawlPlayer, ArcadeCrawlMonster, ArcadeCrawlStairs,
ArcadeCrawlGold, ArcadeCrawlPotion, ArcadeCrawlGear, ArcadeCrawlAmulet,
ArcadeCrawlLog, ArcadeCrawlLogNew, ArcadeCrawlHint, ArcadeCrawlWin and
ArcadeCrawlDead. Sort uses ArcadeSortTitle, ArcadeSortScore, ArcadeSortHint,
ArcadeSortTube, ArcadeSortCursor, ArcadeSortMsg, ArcadeSortWin,
ArcadeSortStuck, ArcadeSortAssist (the tubes a hint points at) and
ArcadeSortC{1..9} for the ball colours.

8. EXTENDING                                                *arcade-extending*

|arcade#ui#open()| takes a controller dict and owns the buffer, the mappings
and the redraw, so a new game only supplies state, a draw function and key
handlers: >

    function! s:draw(state) abort
      return {'lines': ['hello'], 'hl': [[0, 0, 5, 'Question']]}
    endfunction

    function! s:on_key(ctl, key) abort
      let a:ctl.state.count += 1
    endfunction

    call arcade#ui#open({
          \ 'name': 'arcade://demo',
          \ 'filetype': 'arcadedemo',
          \ 'state': {'count': 0},
          \ 'draw': function('s:draw'),
          \ 'keys': {'<Space>': function('s:on_key')}})
<
Highlight spans are [line (0-based), byte start, byte end, group]; the
surface translates them to text properties or extmarks. Draw functions are
pure, which is what makes the games testable headlessly (see test/run.vim).
